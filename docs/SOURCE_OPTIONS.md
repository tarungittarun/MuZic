# MuZic source options

**Research snapshot: 2026-10-25.** No source has been integrated as part of this review. This is a product/rights screening, not legal clearance. API access is not proof of permission to stream, save, or synchronize a recording with lyrics/video. Re-check current terms, availability in India, and track-level rights before implementation; retain any required provider/license attribution.

## Shortlist

| Option | What it offers | Fit for MuZic |
| --- | --- | --- |
| **Local or user-supplied files** | Import and play audio the user already has access to. | **Best current option for offline playback and lyric-video work**, provided the user has the necessary rights to use the file in each way. Keep files local or in the user-selected folder; do not imply that importing a file grants copyright permission. |
| **Jamendo Music API** | Searchable independent catalog with metadata, stream/download fields, per-track Creative Commons information, and an `audiodownload_allowed` flag. [API overview](https://developer.jamendo.com/v3.0/docs) · [tracks endpoint](https://developer.jamendo.com/v3.0/tracks) · [API terms](https://devportal.jamendo.com/api_terms_of_use) | **Not a drop-in source for MuZic's offline/download workflow.** Jamendo's published API terms say use is free for non-commercial applications, commercial use requires contacting Jamendo, and applications must not be designed to cache content or offer offline access. Those terms were last modified in 2013, so obtain written confirmation of current terms before relying on them. `audiodownload_allowed` is not a blanket grant for offline storage, commercial use, or lyric-video synchronization. Jamendo Licensing is a separate product; its catalog licenses are project-, territory-, and use-specific and do not automatically create a general on-demand music catalog. Use Jamendo only after written approval covers this app's exact streaming, storage, and video-export uses and the applicable track rights. |
| **Audius** | Search and stream APIs for a creator-oriented catalog. Its published Free API plan lists 10 requests/second and 500,000 requests/month. [API reference](https://docs.audius.org/api/) · [plans](https://api.audius.co/plans) · [developer SDK/security guidance](https://docs.audius.co/sdk/) · [terms/OML update](https://blog.audius.co/posts/audius-terms-of-service-update) | **Most promising candidate for an online creator-catalog prototype, subject to rights checks.** Audius says its Open Music License governs API use and creators control access; its 2026 terms update says uploads default to All Rights Reserved. Therefore an API result or playable stream is not proof that a track may be downloaded, stored offline, redistributed, or synchronized with exported video. Confirm the current API terms and each track's permissions before use. Audius documents its API key as suitable for client-side use but says a user-authorized bearer token is backend-only—never put that bearer token in an APK. |
| **Internet Archive** | Searchable archival collections, with item metadata and media access through documented APIs. [API documentation](https://archive.org/developers/index-apis.html) | **Possible niche source for clearly licensed archival/public-domain recordings**, not a modern licensed music catalog. Rights and terms are item-specific: require an explicit applicable license or permission for streaming, downloads/offline storage, and lyric-video synchronization for each item. Do not infer rights from an item being publicly accessible. |
| **MusicBrainz / ListenBrainz** | MusicBrainz supplies music metadata and identifiers; ListenBrainz supplies listening-history and recommendation/playlist data. [MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API) · [ListenBrainz API](https://listenbrainz.readthedocs.io/en/latest/users/api/index.html) | Useful **metadata and discovery companions only**; neither is an audio-streaming catalog. |

## Official mainstream integrations (not offline/export sources by default)

- **Apple MusicKit for Android** provides official subscriber sign-in and playback. MusicKit content cannot be downloaded or modified; shareable audio/video needs separate synchronization/adaptation rights. [Android MusicKit](https://developer.apple.com/musickit/) · [App Review Guidelines §4.5.2](https://developer.apple.com/app-store/review/guidelines/)
- **Spotify** is a poor fit for this multi-source lyric-video workflow: Spotify's policy prohibits integrating Spotify content with another service and synchronizing recordings with visual media. Streaming access is also subject to Spotify's subscriber and developer-mode requirements. [Developer policy](https://developer.spotify.com/policy) · [quota modes](https://developer.spotify.com/documentation/web-api/concepts/quota-modes)
- **Deezer** guidelines describe 30-second API clips, prohibit exposing full-track URLs to end users, and prohibit local/offline storage. Use only an authorized SDK playback flow if current developer access is available; it is not a direct-download source. [Developer guidelines](https://developers.deezer.com/guidelines)
- **SoundCloud** is creator-oriented, but its API terms/help restrict downloading, persistent storage, commercial API use, and mixing tracks into videos; its current app-registration guide also imposes an Artist Pro requirement. It is not a fit for MuZic's offline and lyric-video workflow without an explicit agreement. [App registration](https://developers.soundcloud.com/docs/api/register-app) · [terms](https://developers.soundcloud.com/docs/api/terms-of-use) · [public API help](https://help.soundcloud.com/hc/en-us/articles/115003446727-SoundCloud-Public-APIs)
- **TIDAL** may be investigated through its official developer program, but confirm current access, territory, attribution, playback, offline, and video-synchronization terms before adoption. [TIDAL for Developers](https://support.tidal.com/hc/en-us/articles/23052303648529-Tidal-for-Developers) · [official SDK organization](https://github.com/tidal-music)

Do not scrape private stream URLs or reuse credentials from any service. Keep any provider integrations on documented, authorized APIs and preserve required attribution even if ordinary source chips use generic labels.

## Recommendation

1. Keep local/user-supplied audio as the current offline source, with a clear reminder that the user must have rights for playback, copying, and any video export.
2. If adding an online source, prototype Audius for discovery/streaming only after reviewing its current API terms and the permissions for each track. Do not enable downloads, persistent storage, or video export based only on API availability.
3. Do **not** prototype Jamendo Music API as a drop-in offline catalog under its published API terms. First obtain written confirmation or a commercial/mobile/offline agreement that explicitly covers MuZic's use; review any Jamendo Licensing catalog product separately.
4. For mainstream catalog audio, offline playback, and lyric-video export together, plan on a negotiated license/partnership or user-supplied licensed media. The reviewed consumer streaming APIs are not a general permission to move recordings into MuZic's export path.

The current generic “Source A / Source B” labels are a UI choice, not concealment: the APK and network traffic can still identify integrations. Required provider/license attribution must remain visible.
